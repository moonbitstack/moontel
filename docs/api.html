trace

moonbitstack/moontel/trace

The span model, the tracer that mints spans, the four samplers, and the two traits a caller implements: Sink for where spans go and Sampler for what is kept. Nothing here reads a clock, opens a socket or looks at a header.

struct ParentBased Sampler

Follows the parent's decision and asks root only when there is no parent.

This is the sampler to give a service, because it is what keeps a distributed trace whole: the hop that made the decision decided for the whole trace, and every later hop obeys it instead of rolling its own dice.

struct Ratio Debug · Sampler

struct TraceState Eq · Debug

Vendor state travelling with the trace, as an ordered list of at most 32 list-members (W3C Trace Context §3.3.1).

It is a list, not a map: the order is what a hop writes back, the first member belongs to the closest hop, and two members may not share a key. The update operations return a new state rather than editing this one, so that a caller holding the state that arrived cannot change what it arrived as.

fn TraceState::parse(StringView) -> Self raise Refused

Parse a tracestate header value.

Strict on purpose: a list-member that does not match the grammar or a list longer than 32 members refuses the whole header. A hop that kept the parseable half of a broken tracestate would hand the next hop something the sender never wrote, and W3C Trace Context §3.3.1 asks for the header to be dropped instead.

The one place the reading is wider than §3.3.1's ABNF is the key: the W3C Trace Context's reference parser is followed there, so foo@ and foo@@bar are list-members like any other. check_key says why, and says what is still out.

A key that appears twice is the one thing handled member by member: the first member with that key wins and the later one is dropped, which is the choice W3C Trace Context level 2 allows ("pass the duplicate on as-is or drop one of them") and the one W3C Trace Context's reference parser makes.

Whitespace before a member and after a value is dropped, as is whitespace around the commas; whitespace anywhere else is part of a key or a value that the grammar does not allow.

trait Sink

Where finished spans go.

This is the one seam this library leaves open: exporting to OTLP, to a file, to a ring buffer that a background task drains, or to nothing at all is the caller's business, and the shapes that do it belong to whoever owns the transport. A sink is called on the task that finished the span, so an implementation that writes to a socket should hand the span to a queue rather than block the request.

A sink receives every recorded span, including the ones the sampler dropped from the trace: SpanData::sampled is the bit that separates "keep for counting" from "send to the backend".

propagate

moonbitstack/moontel/propagate

W3C Trace Context and W3C Baggage at the header level: what the values look like on the wire, how to read them off a request, and how to put them back on the next one. The two calls a service uses are extract and inject.

fn extract(Array[(String, String)]) -> Extracted

Read the propagation headers out of headers, which is the shape both an ASGI scope and an outgoing request carry.

Header names are matched without regard to case; a value is taken as it is, with the whitespace around it dropped.

Two traceparent headers refuse each other: the specification says a request with more than one is invalid, and picking one of the two would be guessing which proxy wrote the one that matters. Several tracestate or baggage headers are combined in order, as RFC 7230 allows a field to be split across lines.

A header that does not parse leaves that field empty and the rest intact: a mangled tracestate must not cost a hop the trace, and a mangled baggage must not cost it the trace either.

fn inject(Array[(String, String)], Extracted) -> Array[(String, String)]

Put extracted back into headers: the propagation headers already there are removed and rewritten from the context and the bag, and everything else is left exactly as it was.

Rewriting rather than appending is what makes this safe to call on a request that already carried a context — the one from the sender must not survive next to the one this hop decided on.

fn parse(StringView, tracestate? : StringView) -> @trace.TraceContext raise @trace.Refused

A parsed traceparent, plus the vendor state that came with it.

version is kept even though nothing here acts on it: a caller debugging a failed handshake wants to know which version of the header the other side spoke, and a version above zero may one day carry fields this library does not read.

The ids are validated on the way in — sixteen and eight octets, neither all zero — because a context that fails that is not a trace to join, and passing it on would make a broken hop look like a working one.

fn parse_traceparent(StringView) -> @trace.TraceContext raise @trace.Refused

Parse a traceparent header value, without any vendor state.

The grammar is W3C Trace Context §3.2:

``text version(2)-trace-id(32)-parent-id(16)-trace-flags(2) ``

A version this library does not know may append fields, but only after a -: 00 headers end at 55 characters, and 00-…-01.whatever is refused rather than read as a version-0 header with a suffix. Version ff is refused by the specification, as is an all-zero id.

Whitespace around the value is dropped. HTTP allows OWS around a field value, and W3C Trace Context's examples send it; whitespace anywhere inside is refused as the illegal character it is.
